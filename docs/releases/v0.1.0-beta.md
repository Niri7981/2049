# Yosh v0.1.0 Beta — Apple Silicon

Yosh gives AI agents the ability to make real payments without giving them access to your private keys. This Beta contains the native macOS app, local backend, and Codex MCP bridge.

**Requirements:** Apple Silicon (arm64), macOS 15 or later. Intel Macs are not included in this Beta. Node.js, Homebrew, and a source checkout are not needed to run the installed app.

**This Beta is not Apple-notarized and does not have a Developer ID signature.** The app uses an ad hoc signature; macOS may block the first launch. Only approve the app if you trust this project's release. Managed Macs may restrict this approval.

**Clean-Mac installation and first launch after an internet download have not yet been verified.** Local installed-runtime and DMG checks passed; they do not replace those acceptance tests.

## Install (English)

1. Download `Yosh-0.1.0-beta-arm64.dmg` from this release and open it.
2. Drag **Yosh** into **Applications**, then eject the DMG.
3. Try opening Yosh from Applications.
4. If macOS blocks it, open **System Settings → Privacy & Security**.
5. Find the message for Yosh, choose **Open Anyway**, and confirm **Open**. Authenticate if macOS asks.

This approves Yosh individually. Do not globally disable Gatekeeper. macOS Keychain access prompts are separate from first-launch approval; review and complete them in the system dialog. See [Apple's opening instructions](https://support.apple.com/en-us/102445).

To verify the download, place the DMG and its `.sha256` asset in the same folder and run:

```sh
shasum -a 256 --check Yosh-0.1.0-beta-arm64.dmg.sha256
```

## Beta limitations

- Current payment support: x402 V2, Solana Mainnet native USDC, supported exact flow, GET and JSON POST resources. This is not a general wallet or arbitrary signing interface.
- Beta updates retain the app's existing bundle ID and data locations. Ad hoc signing can cause macOS to request Keychain access again.
- Packaging checks and local installed-runtime checks do not establish a clean-machine or downloaded-app installation result. Those scenarios still require testing; no transaction is needed for installation testing.
